    **1. Create src/components/OnboardingRedirect.tsx (per D-01, D-03):**

    IMPORTANT: Per D-01, this component must use the `isNew` flag from `/api/user/init` and persist an `onboardingShown` flag so the redirect fires ONCE only -- NOT on every dashboard visit. The previous design using `snapshot.completed` was incorrect because it would redirect on EVERY visit until onboarding is completed, not just the first sign-in.

    ```typescript
    'use client';

    import { useEffect, useState } from 'react';
    import { useAuth } from '@clerk/nextjs';
    import { useRouter } from 'next/navigation';

    const ONBOARDING_SHOWN_KEY = 'onboardingShown';

    export function OnboardingRedirect() {
      const { isSignedIn, isLoaded } = useAuth();
      const router = useRouter();
      const [checked, setChecked] = useState(false);

      useEffect(() => {
        if (!isLoaded || !isSignedIn || checked) return;

        // Check localStorage first -- if onboardingShown is set, skip entirely
        const alreadyShown = localStorage.getItem(ONBOARDING_SHOWN_KEY);
        if (alreadyShown === 'true') {
          setChecked(true);
          return;
        }

        // Call /api/user/init to check isNew flag (per D-01)
        // This endpoint returns isNew: true ONLY on first-ever sign-in
        // (when user has no username yet). After first call, isNew is false.
        fetch('/api/user/init', { method: 'POST' })
          .then(r => r.json())
          .then(data => {
            if (data.isNew) {
              // First-time user -- redirect to onboarding and persist the flag
              localStorage.setItem(ONBOARDING_SHOWN_KEY, 'true');
              router.replace('/onboarding');
            } else {
              // Returning user -- mark as shown so we never check again
              localStorage.setItem(ONBOARDING_SHOWN_KEY, 'true');
            }
            setChecked(true);
          })
          .catch(() => {
            // On error, don't redirect -- let user use the dashboard
            setChecked(true);
          });
      }, [isLoaded, isSignedIn, checked, router]);

      return null; // Invisible component, only performs redirect logic
    }
    ```

    Key behaviors per D-01:
    - Uses `isNew: true` from `/api/user/init` to detect first-time users (NOT snapshot.completed).
    - Stores `onboardingShown` in localStorage so redirect fires ONCE per browser, even if user dismisses onboarding without completing it.
    - Does NOT redirect returning users who haven't completed onboarding -- they can access the dashboard and use the Sidebar "Onboarding" link (per D-02) if they want to revisit.
    - Uses `router.replace` (not push) so `/onboarding` replaces history entry (per D-03).
    - On error, fails open (user stays on dashboard).
    - The `checked` flag prevents re-fetching on re-renders within a session.

    NOTE: `UserAccountSection` already calls `/api/user/init` for users without a profile. This component may make a second POST in the worst case (first visit ever), but `/api/user/init` is idempotent -- the second call will return `isNew: false` since the first call already assigned a username. This is acceptable for a one-time event.
