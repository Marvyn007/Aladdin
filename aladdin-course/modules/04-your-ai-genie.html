Your AI Genie

How Aladdin uses AI to parse resumes, generate cover letters, and tailor your resume to each job

Aladdin uses AI for three distinct tasks — each more sophisticated than it looks.

📤

Resume Parsing

Upload a PDF, get back structured JSON: your name, skills, work history, frameworks. The AI reads your resume like a human would.

✉️

Cover Letter Generation

Feed the AI your resume + the job description, get back a tailored HTML cover letter — generated word by word, live in your browser using SSE.

📄

Resume Tailoring

A two-pass pipeline rewrites every bullet point on your resume to match the job description, with validators to ensure nothing gets fabricated. Not find-and-replace — actually rewritten.

AI doesn't replace your judgment — it amplifies your preparation. Every generated document starts from your actual experience and the specific job you're applying to. The AI is a ghostwriter who has read your entire portfolio AND the job posting — and writes every document from scratch, tailored to that specific audience.

How a PDF Becomes Data

A PDF is just pixels to a computer — it has no idea what a "skill" or "job title" is. Resume parsing uses an LLM to read the text and extract structured fields the scoring algorithm can use.

1
User uploads PDF

Browser sends it as a file to POST /api/resume — a dedicated API route that handles the upload.

2
pdf-parse extracts raw text

The pdf-parse library strips the PDF formatting and pulls out plain text from the buffer. Think of it as photocopying without the layout.

3
LLM reads and extracts fields

LLM reads the raw text and identifies: name, contact info, skills, work history, education, frameworks, and languages. It understands context, not just keywords.

4
Structured JSON saved to database

The extracted fields are formatted as JSON and saved to the resumes table in the database — one record per user.

5
All future scoring uses this data

Every job match score, every cover letter, every tailored resume — all powered by this structured data. The PDF is never re-read. Parse once, use everywhere.

This is called "structured extraction" — turning messy human text into machine-readable fields. It is one of the most valuable things you can do with an LLM, and it powers every feature that follows.

Why the Cover Letter Types Itself

Cover letters don't wait for the full AI response — they stream word by word using Server-Sent Events (SSE). The server keeps a connection open and sends text chunks the moment the AI generates them.

CODE 
function createSSEStream(req: Request) {
  const encoder = new TextEncoder();

  const stream = new ReadableStream({
    async start(controller) {
      const sendEvent =
          (event: string, data: any) => {
        const message =
          `event: ${event}\n` +
          `data: ${JSON.stringify(data)}\n\n`;
        controller.enqueue(
          encoder.encode(message));
      };

      const { userId } = await auth();
      if (!userId) {
        sendEvent("error",
          { message: "Unauthorized" });
        controller.close();
        return;
      }

      sendEvent("stage", {
        stageId: "stage1_load-job",
        name: "Loading job details...",
      });
PLAIN ENGLISH

createSSEStream(req) → Set up a live data channel — like opening a radio station that broadcasts as content is produced

new TextEncoder() → Converts JavaScript strings to bytes that the network can transmit

new ReadableStream({ start(controller) {...} }) → Create an open pipe — data will be pushed through it as it becomes available, not all at once

sendEvent(event, data) → Format and send one message in the SSE format: event type + JSON data + blank line separator

controller.enqueue(...) → Push one chunk of data through the pipe RIGHT NOW

await auth() → Verify the user is logged in before doing any AI work — check ID before letting anyone in

sendEvent("error", ...) → If not logged in, send an error event and close the connection

sendEvent("stage", {...}) → Tell the browser "stage 1 is starting" — this updates the progress indicator the user sees

Server-Sent Events (SSE) is a browser technology that keeps a connection open between server and browser. The server can push data at any time. This is how the cover letter appears to type itself — each chunk of words arrives as a separate event the moment the AI produces it.

Not Find-and-Replace — Actually Tailored

Tailoring your resume isn't just swapping keywords. Aladdin runs a two-pass pipeline that rewrites each bullet point individually, then polishes the whole thing for consistency.

Pass 1 Per-Bullet Rewrites
1
Parse resume PDF into structured data

Sections, roles, and individual bullet points are identified and stored as separate objects.

2
Embed the job description into vector chunks

The job description is split and converted to embeddings so we can find the most relevant parts for each bullet.

3
For each bullet: retrieve the most relevant job description chunks

Semantic search finds which parts of the job posting are most relevant to each specific bullet point.

4
Call LLM: "Rewrite this bullet to highlight the skills this job needs"

Each bullet is rewritten in context — it understands what this specific role is looking for.

Pass 2 Role Assembly
5
Combine all rewritten bullets for each work role

All the individually-rewritten bullets for each job are assembled back together as a role section.

6
Call LLM again: "Polish this role section — fix grammar, ensure consistent tone"

The second LLM call acts as an editor pass — it makes all bullets feel like they came from the same voice.

7
Run validators

Three safety checks: no deleted bullets — every original bullet must appear. No fabricated experience — no invented companies or roles. No invented skills — only skills from your original resume.

CODE 
export async function generateTailoredResume(
  params: GenerateTailoredResumeParams
): Promise<TailoredResumeOutput> {
  const { resumePdf, linkedinPdf,
    linkedinData, jobDescription } = params;
  const model =
    process.env.LLM_MODEL
    || "openai/gpt-4o-mini";

  const resumeBuffer =
    Buffer.isBuffer(resumePdf)
      ? resumePdf
      : Buffer.from(
          await (resumePdf as File)
            .arrayBuffer());

  const resumeParseResult =
    await parsePdfToDynamicResume(
      resumeBuffer);

  if (params.onProgress) {
    params.onProgress("complete",
      { stageId: "stage2_resume-parse" });
  }
PLAIN ENGLISH

GenerateTailoredResumeParams → Everything the pipeline needs: your resume PDF, optional LinkedIn PDF, and the target job description

const model = process.env.LLM_MODEL || ... → Which AI model to use — read from config so it can be swapped without code changes

Buffer.isBuffer(resumePdf) ? resumePdf : Buffer.from(...) → Handle two cases: PDF already in memory, or PDF coming as a File object that needs to be read

parsePdfToDynamicResume(resumeBuffer) → Extract text from the PDF bytes and structure it into JSON (roles, bullets, skills)

params.onProgress("complete", {...}) → Send a progress update to the streaming client — "Step 2 done!" updates the progress bar the user sees

The two-pass approach matters because a single-pass rewrite often produces inconsistent tone across bullets. Pass 2 is the "editor" pass — it makes everything coherent. Think of Pass 1 as a team of writers each drafting one sentence, and Pass 2 as a single editor reading the whole thing aloud.

How Aladdin Knows Which Jobs Are a Good Match

Before any AI is involved, a pure math algorithm scores each job 0–100 against your resume. No AI needed — just text matching and weighted arithmetic.

🎯
Role Match 30 pts

How similar is the job title to your past roles? Uses Jaccard similarity on shared words.

🛠️
Skill Match 50 pts

How many of your skills appear in the job description? More skills = more points, with diminishing returns past 15 matches.

📍
Location Match 10 pts

Remote job? Full 10 pts. Your city? 10 pts. Elsewhere? 5 pts. Location matters less than skills, so its weight is small.

📋
Base Score 10 pts

You uploaded a resume. That's worth something — every scored applicant starts with a floor of 10 points.

CODE 
// 3. ROLE MATCHING (30 Points)
const titleSimilarity =
  calculateTextSimilarity(
    jobTitle, targetRoles);
components.roleMatch =
  Math.min(30,
    Math.ceil(titleSimilarity * 100));

// 4. SKILL MATCHING (50 Points)
let foundSkills = 0;
allSkills.forEach(skill => {
  if (jobText.includes(skill)) {
    foundSkills++;
  }
});
components.skillMatch =
  Math.min(50,
    Math.ceil(foundSkills * 3.5));
PLAIN ENGLISH

calculateTextSimilarity(jobTitle, targetRoles) → Measure how similar two strings are: count the shared words, divide by total unique words (Jaccard similarity). Returns 0.0 to 1.0.

Math.min(30, Math.ceil(...)) → Cap at 30 points — role match can never exceed its category maximum

allSkills.forEach(skill => if(jobText.includes(skill))) → For each skill on your resume, check if that exact word appears in the job description

foundSkills++ → Count up every skill match

Math.ceil(foundSkills * 3.5) → 1 matching skill = 3.5 pts, 10 skills = 35 pts, 15+ skills → capped at 50 pts
