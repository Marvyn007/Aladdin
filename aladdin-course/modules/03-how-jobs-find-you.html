The 6 Correspondents

Every few minutes, 6 different adapters are running in the background, fetching fresh jobs from their assigned sources. Think of them as six specialized journalists — each fluent in a different job board's language.

🌿
Greenhouse
Polls company career pages via their public ATS API. Used by hundreds of tech companies.
🔧
Lever
Another ATS with its own public board API.
🎭
The Muse
REST API with 10,000+ jobs. Requires an API key to authenticate requests.
🌍
Arbeitnow
Open REST API, no key needed. 2,000+ remote jobs from a European-founded board.
🏔️
Himalayas
Remote-first job board REST API with 5,000+ listings. Focused entirely on remote-friendly roles.
⚙️
Workday
Scrapes Workday cloud portals using XPath. No official API available, so Aladdin reads the raw page structure.

The Adapter Pattern

All 6 adapters speak the same language — they all implement a SourceAdapter interface with a poll() method. Like a universal power adapter: the wall socket is different in every country, but the plug coming out is always the same.

CODE 

export class GreenhouseAdapter
    implements SourceAdapter {
  name = 'greenhouse' as const
  private lastRequestAt = 0

  private async rateLimit():
      Promise<void> {
    const elapsed =
      Date.now() - this.lastRequestAt
    if (elapsed < RATE_LIMIT_INTERVAL_MS) {
      await new Promise((r) =>
        setTimeout(r,
          RATE_LIMIT_INTERVAL_MS - elapsed))
    }
    this.lastRequestAt = Date.now()
  }

  async poll(target: PollTarget):
      Promise<NormalizedJob[]> {
    await this.rateLimit()
    // ... fetch and normalize jobs
  }
}
PLAIN ENGLISH

implements SourceAdapter — This class signs a contract: it will have a poll() method that returns normalized jobs — same shape as every other adapter.

name = 'greenhouse' — Self-identification tag used in logs and task routing so the system knows which adapter ran.

lastRequestAt = 0 — Timestamp of the last API request — used to enforce politeness delays between calls.

rateLimit() — Before every request, check: has enough time passed? If not, wait. This prevents getting blocked by Greenhouse's servers.

elapsed < RATE_LIMIT_INTERVAL_MS — Have we waited long enough since the last request?

await new Promise(...) — Pause execution for the remaining wait time — this is how JavaScript "sleeps" without freezing the whole program.

this.lastRequestAt = Date.now() — Record that we just made a request so the next call can calculate the wait correctly.

poll(target) — The main method: given a company, fetch all their open jobs and return them in the standard format.

The Adapter Pattern is one of the most powerful in software engineering. Adding support for a new job source means writing ONE new class that implements SourceAdapter — the rest of the pipeline just works. You could ask an AI to "create a LinkedInAdapter that implements SourceAdapter" and the entire system would pick it up automatically.

The Editor Who Never Apologizes

After jobs are fetched, every single one runs through the cleanup filter. It's intentionally aggressive — missing a good job is fine, but showing you a bad one wastes your time.

1
🚫 Auto-Delete: Senior titles

Title contains "Senior", "Lead", "Principal", "Manager", "Director", "VP" — immediately rejected. These are not entry-level roles regardless of the job description.

2
🚫 Auto-Delete: Too much experience required

More than 2 years of experience explicitly stated in the description — auto-deleted. The filter parses the description looking for phrases like "5+ years required."

3
🚫 Auto-Delete: Wrong field

Healthcare, finance, HR, sales, marketing, legal — out. Aladdin is for software engineers, not every job that uses a computer.

4
🚫 Auto-Delete: Bad description

Fewer than 3,000 characters or placeholder text detected (e.g., "click to apply", "view full description") — the job content didn't load properly, so it gets dropped.

5
✅ Passes all checks

Job survives every filter — it's saved to the database and appears in your feed. Only the best reach you.

The Filter in Code

CODE 

export const MIN_DESCRIPTION_LENGTH
  = 3000;

export const CONFIDENCE_THRESHOLDS = {
  description: 0.6,
  date: 0.5,
  location: 0.4,
} as const;

const PLACEHOLDER_PATTERNS = [
  /view full description/i,
  /click to apply/i,
  /please log in/i,
  /sign in to view/i,
] as const;
PLAIN ENGLISH

MIN_DESCRIPTION_LENGTH = 3000 — Reject any job with fewer than 3,000 characters in the description. A real job posting is detailed; a stub is not.

CONFIDENCE_THRESHOLDS — Minimum confidence scores for scraped data. If the scraper isn't confident enough it got the real content, the job is rejected.

description: 0.6 — Must be at least 60% confident the description field is real content, not garbled HTML or an error message.

PLACEHOLDER_PATTERNS — Regex patterns that identify fake descriptions. If these phrases appear, the job page didn't load properly.

/view full description/i — Case-insensitive match for this exact placeholder phrase. The /i means it catches "View Full Description" and "VIEW FULL DESCRIPTION" too.

The philosophy: false negatives (missing a good job) are acceptable. False positives (keeping a bad job) are not. When in doubt, delete.

The Fingerprint System

The same job often appears on multiple sources simultaneously. Before saving any job, the system generates a unique fingerprint (a hash) and checks if it already exists.

1
Take the raw job data

Combine: job title + company name + location + full description. These four fields together uniquely identify a specific job posting.

2
Normalize it

Lowercase everything, trim whitespace from edges, strip special characters. This ensures "Software Engineer, NYC" and "Software Engineer, NYC" produce the same fingerprint.

3
Run SHA-256 hash

A mathematical function that turns the normalized text into a unique 64-character fingerprint. It's one-way — you can't reverse it — and deterministic — same input, always same output.

4
Check the database

Does a job with this exact hash already exist? The database has an index on the hash column so this lookup is nearly instant, even with millions of jobs stored.

5
If yes → skip silently. If no → save it.

Deduplication is silent — no errors, no logs, just a quiet skip. The second copy is discarded without ceremony.

A hash is like a fingerprint for data. Run the same text through SHA-256 twice, you get the exact same output. Change even one character, and the hash is completely different. This makes deduplication both fast and reliable.
